# Архитектура и Документация Проекта ErgoBoost (Часть 1: Обзор и Структура)

## 1. Суть и Цель Проекта
**ErgoBoost** — это комплексное настольное приложение с элементами машинного обучения (Machine Learning) и компьютерного зрения (Computer Vision). Главная цель проекта: интеллектуальный мониторинг эргономики рабочего места пользователя (осанка, усталость глаз, расстояние до монитора, контроль перерывов) для сохранения здоровья при длительной работе за компьютером.

Приложение не просто использует набор жестких правил (Rule-based), но и поддерживает гибкие ML-предсказания (Random Forest / Gradient Boosting), дообучаясь на данных пользователя (Online Learning / Background Training), а также предоставляет глубокую аналитику через локальную базу данных (SQLite) и аналитические инструменты больших данных (PySpark).

## 2. Общая Архитектура
Система разделена на следующие ключевые слои:
1. **Presentation Layer (GUI)**: Реализован на базе `PySide6`. Работает в основном потоке. Обеспечивает интерфейс (Dashboard, Settings, Statistics) и системные функции (System Tray, Hotkeys, Screen Blur Overlay).
2. **Business Logic & Services (Services)**: Модули компьютерного зрения и оркестрации. Работают в фоновом потоке (`MonitoringWorker`). Анализируют кадры с вебкамеры.
3. **Data Access Layer (Data)**: Прямое взаимодействие с локальной базой данных SQLite (`sqlite_repo.py`). Отвечает за логирование метрик, управление сессиями, хранение настроек и исторических событий.
4. **Machine Learning Pipeline (ML)**: Компоненты для классификации осанки (`predictor.py`), горячего дообучения (`online_trainer.py`) и масштабного распределенного анализа данных (`pyspark_analytics.py`, `train_pyspark.py`).

## 3. Технологический Стек
- **Интерфейс:** `PySide6` (Qt for Python).
- **Компьютерное зрение:** `OpenCV` (захват видео), `MediaPipe` (Tasks API: `FaceLandmarker`, `PoseLandmarker`).
- **База Данных:** `SQLite3`.
- **Машинное Обучение:** `scikit-learn` (ML-модели: GradientBoostingClassifier, RandomForest), `PySpark` (распределенная аналитика), `pandas`, `numpy`.
- **Визуализация (Графики):** `matplotlib` (генерация графиков в памяти для GUI), `seaborn`.

# Архитектура и Документация Проекта ErgoBoost (Часть 2: Services и Математика)

Модули в папке `services/` отвечают за основную математическую и аналитическую логику проекта в реальном времени.

## 1. PoseDetector (`services/pose_detector.py`)
Оценивает осанку на основе ключевых точек (landmarks), выдаваемых MediaPipe `PoseLandmarker`.

### Формулы:
1. **Сдвиг головы вперед (Forward Shift):**
   Основан на разнице в глубине (ось Z) между ушами и плечами. 
   - `ear_center_z = (left_ear.z + right_ear.z) / 2`
   - `shoulder_center_z = (left_shoulder.z + right_shoulder.z) / 2`
   - `shoulder_width = abs(left_shoulder.x - right_shoulder.x)` (используется для нормализации).
   - Формула: `forward_shift = (ear_center_z - shoulder_center_z) / shoulder_width`.
   *Чем больше значение, тем сильнее голова выдвинута вперед (сутулость).*

2. **Боковой наклон (Lateral Tilt):**
   Определяется по углу наклона линии, соединяющей плечи, относительно горизонтали.
   - `dx = right_shoulder.x - left_shoulder.x`
   - `dy = right_shoulder.y - left_shoulder.y`
   - Формула: `tilt = atan2(dy, dx) в градусах`.
   *Значение > 0 означает перекос в одну сторону, < 0 — в другую.*

### Сглаживание (Smoothing)
Оба показателя пропускаются через сглаживающий буфер (очередь фиксированного размера, обычно `deque(maxlen=10)`), а возвращается среднее арифметическое (Simple Moving Average). Это устраняет "дрожание" (jitter) ключевых точек MediaPipe.

## 2. BlinkDetector (`services/blink_detector.py`)
Обнаруживает моргания и вычисляет усталость по частоте морганий. Использует `FaceLandmarker` MediaPipe.

### Формула EAR (Eye Aspect Ratio):
Для каждого глаза берутся 6 ключевых точек (например, левый глаз: `p1, ..., p6`, где p1 и p4 - уголки, а p2, p3 и p5, p6 - верхние и нижние веки).
- `EAR = (dist(p2, p6) + dist(p3, p5)) / (2.0 * dist(p1, p4))`
Вычисляется среднее EAR для обоих глаз. Если `EAR` падает ниже порога (например, 0.21), это фиксируется как моргание (используется логика состояний `is_blinking`).

### Оценка усталости (Fatigue):
Считает количество морганий за скользящее окно (обычно 60 секунд) — получается `blink_rate_per_minute`.
- Меньше 8 морганий в минуту: `LOW_BLINK` (глаза пересыхают из-за пристального взгляда в экран).
- От 8 до 30: `NORMAL`.
- Больше 30: `HIGH_BLINK` (стресс, дискомфорт, физическая усталость глаз).

## 3. DistanceDetector (`services/distance_detector.py`)
Оценивает приблизительное расстояние пользователя от экрана.

### Принцип работы:
Поскольку точная глубина по обычной 2D вебкамере неизвестна, используется относительная ширина лица.
- `distance_ratio = abs(left_cheek.x - right_cheek.x)`
Чем ближе лицо, тем большую часть экрана в нормализованных координатах оно занимает. Отношение сравнивается с эталонным (полученным на этапе калибровки).
- `TOO_CLOSE`: `distance_ratio > baseline_ratio * 1.15`
- `TOO_FAR`: `distance_ratio < baseline_ratio * 0.85`

## 4. BaselineCalibrator (`services/baseline_calibrator.py`)
Модуль для создания "эталона" позы конкретного пользователя.
Калибровка длится 3-10 секунд. За это время человек сидит ровно, а система усредняет значения: `forward_shift`, `lateral_tilt`, `distance_ratio`.
В дальнейшем отклонения (Deviations) вычисляются как разность текущих значений и калибровочных (baseline):
- `deviation_fwd = current_fwd - baseline_fwd`
- `deviation_tilt = current_tilt - baseline_tilt`

В `MonitoringWorker` также рассчитывается суммарная жесткость позы (`severity`): 
`severity = abs(deviation_fwd) * 1.5 + abs(deviation_tilt) * 1.0` (веса настраиваются). Если `severity` превышает порог, генерируется алерт.

## 5. BreakReminder (`services/break_reminder.py`)
Отслеживает непрерывное время работы и "настоящие" перерывы.
- `soft_limit` (например, 1.5 часа): Рекомендация отдохнуть.
- `hard_limit` (например, 2 часа): Жесткое требование отдыха.
- `absence_threshold` (например, 10 минут): Если пользователь отсутствует в кадре меньше этого порога, таймер работы ставится на паузу. Если больше этого порога — сессия непрерывной работы сбрасывается (перерыв засчитан).

## 6. AlertManager (`services/alert_manager.py`)
Интегрирован с пакетом `winotify`. Отвечает за:
- Отправку нативных Toast-уведомлений Windows.
- Использование "cooldown" (периода тишины, например 30 секунд), чтобы не спамить уведомлениями при длительной плохой позе.
- Воспроизведение звука Windows при появлении уведомления (опционально, зависит от настроек пользователя).

# Архитектура и Документация Проекта ErgoBoost (Часть 3: Машинное Обучение)

Подсистема Machine Learning (ML) в ErgoBoost делает систему умной: вместо жестко заданных порогов отклонения приложение учится на паттернах пользователя и определяет сложную нелинейную границу между «ОК» и «BAD» позой.

## 1. Predictor (`ml/predictor.py`)
Класс, отвечающий за предсказания (Inference) в реальном времени.
Загружает предварительно обученную модель (файл `.pkl` в `ml/models/`) и скейлер (обычно `StandardScaler`).
Использует классификатор из библиотеки `scikit-learn` (в проекте по умолчанию `GradientBoostingClassifier` или `RandomForestClassifier`).

### Признаки (Features):
На вход предсказателю подаются отклонения (Deviations), а не сырые координаты, что делает модель универсальной (после калибровки):
1. `deviation_fwd`: Отклонение головы вперед от эталона.
2. `deviation_tilt`: Отклонение плеч от эталона по углу.
3. `shift_abs`: Модуль отклонения головы (`abs(deviation_fwd)`).
4. `tilt_abs`: Модуль отклонения угла наклона (`abs(deviation_tilt)`).
5. `shift_x_tilt`: Взаимодействие признаков (`shift_abs * tilt_abs`), помогающее улавливать сложные комбинированные позы (например, сутулость + сильный перекос одновременно).

Модель возвращает вероятность принадлежности к классу "BAD" (плохая поза). Если вероятность > 0.5, статус устанавливается в "BAD". Вероятность масштабируется и используется в качестве "Severity" (серьезности).

## 2. Online Trainer (`ml/online_trainer.py`)
Инновационная часть системы — фоновое дообучение. 
Когда пользователь работает в режиме "Rule-based" (по строгим формулам), генерируются события с предсказанными метками (псевдо-разметка). Либо используются размеченные пользовательские сессии.

### Механика:
- Запускается в фоновом потоке (`threading.Thread`).
- Собирает последние тысячи записей из БД (`sqlite_repo.py`).
- Обучает новый `GradientBoostingClassifier`.
- **Предотвращение Data Leakage:** Для кросс-валидации (CV) используется `GroupKFold`, где в качестве "группы" выступает `session_id`. Это означает, что модель не "заучивает" сильно похожие кадры из одной и той же сессии (из-за временной корреляции), а учится обобщать паттерны на новые сессии.
- Если новая модель показывает F1 Score > 0.85, происходит "горячая подмена" (Hot Swap) модели в оперативной памяти (`self.ml_predictor.model = new_model`), без прерывания работы GUI или камеры.

## 3. PySpark Pipeline (`ml/train_pyspark.py`, `ml/train_posture_model.py`)
Для работы с "Big Data" (крупными наборами исторических данных) реализован пайплайн на Apache Spark.
- Связывается с SQLite через JDBC драйвер (`sqlite-jdbc`).
- Использует датафреймы Spark (PySpark SQL) для агрегации и джоинов таблиц `sessions` и `posture_events`.
- Использует `VectorAssembler` для объединения фичей и MLlib `GradientBoostedTrees` (или Random Forest) для распределенного обучения на кластере.
- Вычисляет `MulticlassClassificationEvaluator` (F1, Accuracy) и сохраняет логи обучения в JSON.

## 4. Сбор Датасета и Оценка (`test/collect_posture_data.py`, `test/evaluate_model.py`)
Скрипт для ручной разметки. Включает камеру, калибруется, и позволяет по нажатию кнопок (O - OK, B - BAD) сохранять в CSV датасет с сырыми признаками и реальными (True Label) метками.
Скрипт оценки (`evaluate_model.py`) генерирует отчет: Confusion Matrix, ROC-кривую, графики распределения признаков (KDE) и важности признаков (Feature Importance) через `seaborn`.

# Архитектура и Документация Проекта ErgoBoost (Часть 4: Данные и Аналитика)

Слой доступа к данным (Data Layer) построен на `SQLite3`, что идеально подходит для легковесного локального настольного приложения без внешних зависимостей.

## 1. Схема Базы Данных (`data/schema.sql`)
Структура БД нормализована и состоит из следующих основных таблиц:
- `users`: Пользователи (id, username, password_hash, salt). Пароли хешируются с помощью PBKDF2 (SHA-256) с 600,000 итерациями.
- `user_settings`: Ключ-значение (`setting_key`, `setting_value`) для хранения параметров конфигурации в формате JSON-строк.
- `sessions`: Главная сущность. Хранит информацию о конкретном периоде работы за ПК (start_time, end_time, duration). В конце сессии вычисляются агрегаты: `posture_score`, `good_posture_percent`, `avg_blink_rate`, `total_active_seconds`.
- `posture_events`: Лог осанки (секундный интервал). Поля: `forward_shift`, `lateral_tilt`, `posture_status` (OK/BAD), `severity`.
- `eye_events`: Лог морганий. Поля: `blink_count`, `ear`, `blink_rate_per_min`, `fatigue_level`.
- `distance_events`: Отношение дистанции. Поля: `distance_ratio`, `distance_status`.
- `presence_events`: Учет присутствия/отсутствия в кадре.

*Индексы:* Созданы индексы по `session_id` и `timestamp` для быстрого построения временных рядов (Timeline) в GUI.

## 2. Доступ к Данным (`data/sqlite_repo.py`)
Паттерн Репозиторий изолирует SQL-запросы от бизнес-логики.
- `log_posture_event`, `log_eye_event`: Методы инсерта (вставки).
- `get_historical_data`: Джоин таблиц для аналитики.
- `end_session`: Метод финализации. Здесь происходит расчет комплексной оценки за сессию.
  
### Формула Posture Score (Балл сессии)
Оценка вычисляется по шкале от 0 до 100.
1. Начинается с 100 баллов.
2. Вычитается штраф за осанку: `- (100 - good_posture_pct) * 0.5`.
3. Штраф за глаза: Если `avg_blink_rate` сильно отличается от идеального (15), вычитается штраф (максимум 25 баллов).
4. Штраф за расстояние: `- (100 - distance_ok_pct) * 0.25`.

## 3. Аналитика (`analytics/`)
- `analytics_service.py`: Легковесный генератор сводок (Summary) для Dashboard и статистики. Извлекает средний балл (Avg Score) и среднее время (Avg Duration).
- `pyspark_analytics.py`: Расширенный инструмент, применяющий оконные функции (Window Functions) Spark для анализа изменения частоты морганий во времени (`lag()` / `diff`) и построения почасовых паттернов осанки (`hour()`, `dayofweek()`).

## 4. Утилиты (`utils/`)
- `chart_utils.py`: Обертка над `matplotlib`. Рисует графики (Trend, Distribution) в памяти и конвертирует их в `QPixmap` для отображения в PySide6 без сохранения файлов на диск. Учитывает темную тему (Dark Theme) приложения.
- `pdf_report.py`: Использует `matplotlib.backends.backend_pdf.PdfPages` для генерации многостраничного PDF-отчета. Рисует красивые таблицы со сводкой, вердикты и графики трендов (score trend, duration, blink patterns).
- `generate_synthetic_data.py`: Инструмент для создания mock-данных (генерация сотен сессий с реалистичным распределением шума Гаусса, эффектами усталости и случайными перерывами) для нагрузочного тестирования.

# Архитектура и Документация Проекта ErgoBoost (Часть 5: Графический Интерфейс - GUI)

Presentation Layer написан на `PySide6` (официальный биндинг Qt для Python). Используется кастомный темный дизайн (Dark Mode) посредством Qt StyleSheet (QSS), без применения тяжелых фреймворков или сторонних UI-библиотек.

## 1. Точка Входа и Аутентификация
- `ergoboost_app.py`: Инициализация `QApplication`, загрузка системных путей (sys.path). Запускает цепочку окон.
- `gui/auth_window.py`: Использует `QStackedWidget` для переключения между "Sign In" и "Sign Up". Обращается к `AuthService` для сверки хешей паролей через SQLite. При успешной авторизации запускает `ErgoBoostMainWindow`.

## 2. MainWindow (`gui/main_window.py`)
Окно приложения состоит из:
1. **Header (Верхняя панель)**: Имя пользователя, кнопка DND (Do Not Disturb - таймер игнорирования уведомлений) и Sign Out.
2. **QTabWidget**: Переключатель между вкладками.
3. **QSystemTrayIcon (Системный трей)**: Позволяет свернуть приложение в трей. Содержит меню с действиями (Start, Pause, Quit).
4. **Hotkeys**: Регистрирует глобальные/локальные шорткаты (`QShortcut`) для старта/паузы мониторинга и закрытия оверлея.

## 3. Worker Thread (`gui/monitoring_worker.py`)
GUI не должен зависать при выполнении "тяжелых" задач компьютерного зрения.
- Мониторинг вынесен в класс `MonitoringWorker`, который наследуется от `QObject` и помещается в `QThread`.
- Работает по принципу бесконечного цикла, читая кадры из `cv2.VideoCapture`.
- Инстанцирует все модули-детекторы (`PoseDetector`, `DistanceDetector`, `BlinkDetector`, `ML Predictor`).
- Связь с GUI осуществляется через безопасные для потоков механизмы `Signals` & `Slots`:
  - `frame_ready(np.ndarray)` — отправляет обработанный кадр для отрисовки.
  - `metrics_updated(dict)` — словарь всех показателей для обновления текста в интерфейсе.
  - `alert_triggered` / `overlay_requested` — команды для показа нотификаций.

## 4. Вкладки (Tabs)
1. **DashboardTab (`gui/dashboard_tab.py`)**: 
   - `QLabel` для вывода кадра (отрисовывает `QPixmap` из `np.ndarray`).
   - Панель метрик (Светофорная расцветка: зеленый = OK, красный = BAD).
   - Индикаторы `Presence` (за столом / не за столом), таймеры работы, `Overlay Countdown`.
2. **StatisticsTab (`gui/statistics_tab.py`)**: 
   - Асинхронно через `StatsWorker` загружает графики (Score Trend, Session Duration) и Summary.
   - Вывод `QPixmap` с `matplotlib` и создание PDF отчета.
3. **SessionsTab (`gui/sessions_tab.py`)**: 
   - Вывод таблицы `QTableWidget` со списком прошлых сессий пользователя.
4. **SessionDetailDialog (`gui/session_detail_dialog.py`)**:
   - Открывается по клику "Details" в таблице. Загружает `posture_events`, `eye_events` и рисует детальные графики (Timeline) по каждой метрике для конкретной сессии, плюс экспорт в CSV конкретно этой сессии.
5. **ExercisesTab & SettingsTab**: 
   - Текстовая информация (комплексы разминок).
   - Настройка `Settings` (`QCheckBox`, `QComboBox`, `QSlider`), которые синхронизируются в `settings.yaml` и БД.

## 5. ScreenBlurOverlay (`gui/screen_overlay.py`)
"Радикальный" метод уведомления.
- Если плохая поза сохраняется на протяжении определенного времени (`overlay_delay`, например, 4 секунды), `MonitoringWorker` отправляет сигнал `overlay_countdown`.
- Класс `ScreenBlurOverlay` создает прозрачные окна (`Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint`), которые располагаются поверх *всех* активных мониторов пользователя. 
- Начинается отсчет (обратный таймер на экране). Если поза не исправлена, экран затемняется полупрозрачным черным фоном (`QPainter.fillRect` с альфа-каналом), блокируя работу, пока человек не выровняет спину или не нажмет Escape. При закрытии приложения используется `atexit`, чтобы оверлеи гарантированно пропали и не заблокировали ОС.
